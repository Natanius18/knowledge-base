# Code smells

## 1. Long Method
**Что это:** Метод растянут на кучу строк — больше 10-20.

**Почему плохо:** Трудно читать, как длинный текст без абзацев. Легко запутаться, где что.

**Как починить:** Разбей на маленькие методы. Каждый делает одну простую вещь. Например, вместо одного большого — вызови 3-4 коротких.

## 2. Large Class
**Что это:** Один класс делает всё: хранит данные, считает, проверяет — как чемодан с посудой и одеждой.

**Почему плохо:** Когда меняешь — рискуешь сломать всё. Нарушает правило "один класс — одна задача".

**Как починить:** Выдели части в новые классы. Например, расчёты — в отдельный класс.

## 3. Primitive Obsession
**Что это:** Используешь простые типы (строка для email, число для денег) вместо специальных объектов.

**Почему плохо:** Нет проверок: email может быть "abc", деньги — отрицательные. Повтор кода везде.

**Как починить:** Создай класс Email или Money с проверками внутри. Передавай их, а не сырые строки/числа.

## 4. Duplicate Code
**Что это:** Один и тот же кусок кода копипастится в 2+ местах.

**Почему плохо:** Меняешь в одном — забываешь в другом, ошибки множатся.

**Как починить:** Выдели в общий метод или класс. Один раз пишешь — везде используешь.

## 5. Switch Statements
**Что это:** Огромный switch или if-else на типы/статусы.

**Почему плохо:** Добавляешь новый тип — переписываешь всё. Код растёт.

**Как починить:** Используй полиморфизм: каждый тип — свой класс с методом. Или карту (Map) с функциями.

## 6. Feature Envy
**Что это:** Метод А часто лезет в данные класса Б (a.getB().doThis()).

**Почему плохо:** Метод "завидит" чужим данным, нарушает границы классов.

**Как починить:** Перенеси метод в класс Б. Пусть Б сам работает со своими данными.

## 7. Comments
**Что это:** Код засыпан "// объяснениями".

**Почему плохо:** Комменты устаревают, код не понятен сам по себе. Хороший код говорит за себя.

**Как починить:** Удали комменты. Улучши имена переменных/методов. Разбей на методы.

## 8. Dead Code
**Что это:** Неиспользуемые методы, переменные, классы.

**Почему плохо:** Мусор отвлекает, код кажется сложным.

**Как починить:** Удали без жалости. IDE покажет, что не используется.

## 9. Data Clumps 
**Что это:** Всегда передаёшь вместе имя, фамилию, email как отдельные параметры.

**Почему плохо:** Запутанно, легко перепутать порядок.

**Как починить:** Сделай класс Person с этими полями. Передавай один объект.

## 10. Long Parameter List
**Что это:** Метод с 4+ параметрами.

**Почему плохо:** Трудно запомнить, что куда. Легко ошибиться при вызове.

**Как починить:** Сгруппируй в объект (как в Data Clumps) или сделай параметры полями класса.

---

| Запах | Что и как починить                     |
|-------|----------------------------------------|
| Длинный метод | Функция >20 строк. Разбей на мелкие.   |
| Большой класс | Один класс на всё. Раздели на 2-3.     |
| Примитивы везде | Строка вместо Email. Сделай класс.     |
| Дубликаты | Копипаст кода. Выдели в метод.         |
| Switch-монстр | Много if/switch. Полиморфизм или Map.  |
| Завистливый метод | Лезет в чужие данные. Перенеси метод.  |
| Комментарии | "// тут объясню". Удали, улучши имена. |
| Мёртвый код | Неиспользуемое. Удали.                 |
| Группа параметров | Имя+email вместе. Класс Person.        |
| Много параметров | >4 аргумента. Объект вместо списка.
